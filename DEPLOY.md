# Deploying the DM Stats Tracker

## One-time setup (~10 minutes)

### Step 1 — Create a GitHub account
Go to [github.com](https://github.com) and sign up if you don't already have one.

### Step 2 — Create a new repository
1. Click **+** (top right) → **New repository**
2. Name it `dm-stats`
3. Set to **Public**, leave everything else as default
4. Click **Create repository**

### Step 3 — Upload the files
Upload the following from your local folder:
- `index.html`
- `data/games.json`
- `scorecards/index.html`
- `README.md`

Easiest via GitHub Desktop: File → Add local repository → point to the folder → commit → push.

### Step 4 — Enable GitHub Pages
1. In your repo → **Settings** → **Pages** (left sidebar)
2. Under **Source**: Deploy from a branch → **main** → **/ (root)**
3. Click **Save**
4. Wait ~1 minute — a green banner shows your live URL: `https://kgv808.github.io/dm-stats/`

## Updating after a new game

### What to commit
Only `data/games.json` needs to change after each game. Everything else stays the same unless you're making UI changes.

### The pipeline

**Prerequisites:** Python venv with pdfplumber installed.
```bash
cd "data extraction"
.venv\Scripts\activate        # Windows
# or: source .venv/bin/activate  # Mac/Linux
```

**Steps:**

1. Download the PDF scorecard from Spawtz. Save it to:
   - Spring 2025 games → `data extraction/pdfs/Fourways Cricket - Cricket Spring Season 2025 - C3/`
   - Autumn 2026 games → `data extraction/pdfs/Hillfox Cricket - Cricket Autumn 2026 - C1/`
   - Name format: `G7 - Action Sports - Opponent vs Durban Mallus (DD.MM.YYYY HH.MM).pdf`

2. Add the game to `data extraction/scorecard_urls.csv`:
   ```
   Season,SeasonLabel,GameWeek,Date,Opponent,Result,DMScore,OppScore,FixtureID,URL,PDFAvailable
   autumn2026,Autumn 2026,G20,2026-06-10,Opponent Name,win,95,62,1234567,...,Y
   ```

3. Run the extraction pipeline:
   ```bash
   python "data extraction/run_all.py"
   python "data extraction/aggregate.py"
   python "data extraction/build_games_json.py"
   ```

4. Open **GitHub Desktop** → review the diff on `data/games.json` → commit → push.

The live site updates within ~60 seconds.

## Supabase setup (one-time)

The project has a Postgres database on Supabase as an alternative data layer.

### Apply the schema
1. Open the [Supabase SQL Editor](https://supabase.com/dashboard/project/chswumfxdyjstgsddbhd/sql)
2. Paste the contents of `supabase/migrations/20260611000001_initial_schema.sql`
3. Click **Run**

### Seed existing data
```bash
cd "data extraction"
pip install supabase python-dotenv
python migrate_to_supabase.py
```
Requires a `.env` file in the project root (copy from `.env.example` and fill in keys from Supabase → Settings → API Keys).

### Credential security
- **`SUPABASE_ANON_KEY`** — safe to embed in client-side HTML (read-only, RLS enforced)
- **`SUPABASE_SERVICE_KEY`** — server/script use only, never commit to git

## File reference

| File | Purpose | Edit? |
|------|---------|-------|
| `index.html` | Live tracker — reads `data/games.json` | Only for UI changes |
| `index_supabase.html` | Supabase-connected tracker | Update anon key if it rotates |
| `index_games_json.html` | Backup of the games.json version | Don't edit |
| `index_v2.html` | Redesigned UI test | Work in progress |
| `data/games.json` | All game data | Regenerated by pipeline — don't edit by hand |
| `scorecards/index.html` | Scorecard archive viewer | Only to add new seasons |
| `supabase/migrations/` | Postgres schema | Add new migration files for schema changes |
| `data extraction/scorecard_urls.csv` | Fixture metadata | Add one row per new game |
| `data extraction/extract_scorecard.py` | PDF extractor | Only if PDF format changes |
| `data extraction/aggregate.py` | Stats aggregator | Only if stat logic changes |
| `data extraction/build_games_json.py` | JSON builder | Only if games.json structure changes |
| `data extraction/migrate_to_supabase.py` | One-time seed script | Don't re-run — will conflict with existing data |
| `.env.example` | Credential template | Update if new env vars are added |

## Before every commit — checklist

- [ ] Run the full pipeline (run_all → aggregate → build_games_json)
- [ ] Check `data/games.json` diff — verify player counts per game (should be 8 per game)
- [ ] Update `scorecards/index.html` game data if a new game was added
- [ ] Update `README.md` season records if season totals changed
- [ ] Confirm the live site renders correctly after push
- [ ] Confirm `.env` is not included in the commit (should be gitignored)
